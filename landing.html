为什么是 Next

砍掉自托管，把力气全花在 Pages 这一条路上

上游是「Pages + Docker 双模」的通用文件托管；K-Vault-Next 只留一种部署形态， 省下来的复杂度换成了前端统一、鉴权加固、分片上传升级与分享体系重构。

只有一种部署形态

根目录静态页 + functions/ 下的 Pages Functions。 没有 Node 运行时、没有 Dockerfile、没有 GHCR 镜像，也没有 Sentry 埋点。

  • 零运行时依赖
  • 零遥测
  • 无构建命令

七种存储后端，一个入口

Telegram（默认）、Cloudflare R2、S3 兼容、Discord、HuggingFace、WebDAV、GitHub。 前端「存储节点」抽屉支持智能节点选择，超过阈值自动切换后端。

  • 并行上传池
  • 后端缺失直接报错

R2 原生 multipart：单文件上限 100 MB → 10 GB

改用 R2 原生分片上传，暂存位置 auto / r2 / kv 可在后台切换；Telegram 池与分片池分离，并行上传可开关。

分享是「按条目」的

/s/:slug 跳到分享落地页：有效期、访问密码、下载次数上限、自定义短链四项前后端都能设。 预览不计次，点「下载」才计数。

  • 410 过期 / 用量用尽
  • 401 · 403 密码语义

高频配置写 KV，即时生效

config:guest / config:cors / config:upload 三组配置在后台改完立刻生效，不用重新部署；环境变量退化为基线值，随时可重置。

安全是默认值，而不是开关

管理面 fail-closed 登录暴力破解防护 统一限流 堆栈信息脱敏 URL 导入 SSRF 防护 共享依赖本地化 Token scope + 策略 无第三方审核 API
上传调度

文件写进你挑的后端，元数据留在 KV

同一个上传入口切换七种后端；指定后端未配置时不会静默降级到其他后端，而是直接报错—— 少一次「以为传进 R2、其实躺在别处」的意外。

直连与旁路分开走

文件流走存储后端，文件名、目录、分享状态、下载计数走 KV——所以列表页很轻， 删一个文件也不会把整条链路拖慢。

  • /file/[[path]].js 支持任意层级路径
  • /s/:slug 只做跳转，不直接吐流
  • 分片任务与运行时配置都落在 KV

视觉层

模糊不是装饰，是层级

浮层（dock / 菜单 / 模态 / 遮罩）保留 backdrop-filter，静止卡片不挂模糊—— 这是刻意的取舍：卡片底色饱和度已经很高，模糊的视觉收益接近零，却要每帧重算。 下面这块演示区可以当场调参。

底层面板 z-index 1 · 无模糊
中层玻璃 blur(20px) saturate(180%)
顶层卡片 光标跟随 bloom
backdrop-filter: blur(20px) saturate(180%);

折射由 vendored 的 glassfx 提供，Chromium 上走 SVG 位移滤镜；其他引擎自动落到 frost 兜底。低端设备（html[data-perf="low"]）会自动撤掉全部 backdrop-filter。

快速开始

最小部署集，五步

绑定（Bindings）和环境变量都只在部署时注入——改完记得 Retry deployment。 仓库里的 .env.example 是清单，不是配置文件，Cloudflare Pages 不会读它。

  1. 01

    连接仓库到 Cloudflare Pages

    Build command 与 Build output directory 都留空——这个项目没有构建步骤。

    Framework preset: None · Build command: (空) · Output: (空)
  2. 02

    绑定 KV：变量名必须是 img_url

    Settings → Functions → KV namespace bindings。写成环境变量是无效的，这是第一个坑。

    Binding name: img_url → 你的 KV Namespace
  3. 03

    绑定 R2（强烈推荐）：R2_BUCKET

    这是唯一支持原生分片的后端，也是把单文件上限拉到 10 GB 的那条路。

    Binding name: R2_BUCKET → 你的 R2 存储桶
  4. 04

    设置后台账号 BASIC_USER / BASIC_PASS

    公网部署必须设：不设的话管理接口一律返回 503 ADMIN_AUTH_NOT_CONFIGURED（fail-closed）。

    BASIC_USER=admin BASIC_PASS=换成一个足够长的密码
  5. 05

    填一个存储后端凭据

    推荐 Telegram。变量名大小写不用纠结——统一读取层 env-config.js 会把 TG_Bot_Token 与 TG_BOT_TOKEN 都认出来，填一次即可。

    TG_Bot_Token=123456:AA... TG_Chat_ID=-1001234567890

第 6 步（只在绑了 R2 时才需要）

给 R2 配生命周期规则。否则用户传大文件传到一半关掉页面，临时分片会一直占着空间。 访客上传、CORS 白名单、分片暂存后端这三组配置可以直接在后台改，写进 KV 后即时生效。

机器可调用

给人用的后台，也给脚本用的接口

API v1 走 Authorization: Bearer kvault_<tokenId>_<secret>， scope 分 upload / read / delete / paste， 还能挂上后端白名单、MIME 白名单、体积上限、目录前缀、来源主机与限流策略。 机器可读定义见 docs/openapi.yaml。

公开 · 无需 Token 
curl https://your-vault.pages.dev/api/v1/capabilities

# {
#   "success": true,
#   "storage": { "configured": ["telegram", "r2"], ... },
#   "limits":  { "r2": 10737418240, "telegram": 20971520, ... }
# }
scope: upload · 支持 Idempotency-Key 24h 去重 
curl -X POST https://your-vault.pages.dev/api/v1/upload \
  -H "Authorization: Bearer kvault_xxx_yyy" \
  -H "Idempotency-Key: $(uuidgen)" \
  -F "file=@./cover.png" \
  -F "storage=r2" -F "path=/blog/2026"

# 响应里直接带回 links.share：
#   https://your-vault.pages.dev/s/ocean
scope: read / delete 
curl "https://your-vault.pages.dev/api/v1/files?limit=20" \
  -H "Authorization: Bearer kvault_xxx_yyy"

curl "https://your-vault.pages.dev/api/v1/file/blog/2026/cover.png/info" \
  -H "Authorization: Bearer kvault_xxx_yyy"
scope: paste 
curl -X POST https://your-vault.pages.dev/api/v1/paste \
  -H "Authorization: Bearer kvault_xxx_yyy" \
  -H "Content-Type: application/json" \
  -d '{"content":"npm run deploy","language":"bash",
       "expiresIn":86400,"password":"optional"}'
Token 策略：allowedStorages · allowedMimeTypes · maxFileSize · folderPrefix docs/openapi.yaml · docs/agent-integration.md
常见问题

先说清楚，再上手

它和上游 katelya77/K-Vault 是什么关系？

K-Vault-Next 派生自上游，保留了后端能力（多存储、鉴权、API），然后重写了前端、 加固了鉴权、升级了分片上传，并整条移除 Docker 自托管路线。本仓库不是上游的替代品： 如果你要的是「一台 VPS 跑起来、配置存 Redis」，请直接用上游的 Docker 版本。

要花钱吗？

项目本身 MIT，跑在 Cloudflare Pages 免费额度内是零成本。Pages 的 Functions 请求数、 KV 读写、R2 存储与流量都各有免费额度，超出部分按 Cloudflare 定价计费—— 具体额度以 Cloudflare 官方为准。

单文件到底能传多大？

R2 走原生 multipart，上限 10 GB；Telegram 走 Bot API 转发，20 MB；S3 / WebDAV / GitHub 未实现分片，40 MB（GitHub contents 模式 20 MB）；HuggingFace 35 MB；Discord 取保守值 25 MB。 诚实说明：这一代并非全面更强，R2 大幅提升，但没做分片的几个后端低于上游标注值。

后台改配置要重新部署吗？

访客上传、CORS、分片暂存这三组不用：它们是 config:guest / config:cors / config:upload，写进 KV 立刻生效，优先级高于环境变量， 后台还能一键重置回基线。绑定（KV / R2）和其他环境变量则必须重新部署。

有 Docker / 自托管版本吗？

没有，且这是刻意的。Dockerfile、docker-compose、server/ 运行时、 GHCR 镜像构建与配套服务端测试都被移除了。只支持 Cloudflare Pages 一种形态。

会收集我的数据吗？

不会。这一代删掉了 Sentry 依赖与全部埋点代码，所以连 disable_telemetry 这个开关都不复存在——没有遥测代码，也就不需要关闭按钮。内容审核与黑白名单同样已移除， 不调用任何第三方审核 API。
